# 产品范围

## 目标

Bamboo Desktop 是 BambooRoute 的桌面入口。用户安装后登录 Bamboo 账户，由应用自动准备调用配置，再开始聊天或本地任务。用户无需填写厂商密钥、Base URL 或上游模型映射。

产品暂名为 Bamboo Desktop。正式应用名、安装包标识及自有仓库名在发行准备时确定。

## 首版候选范围

以下为后续实现建议，当前均未实现。

| 用户操作 | 预期结果 |
| --- | --- |
| 安装与启动 | 在受支持平台直接运行，不要求普通用户自行安装开发工具链 |
| 登录 Bamboo | 完成账户授权，回到应用，获得对应账户的可用模型与额度状态 |
| 新建会话 | 使用服务端下发并经过验证的默认模型开始对话 |
| 选择工作区 | 清楚显示本地任务访问范围，并可撤回或调整授权 |
| 执行任务 | 展示真实进度、工具操作、需要确认的动作和结果 |
| 查看文件修改 | 查看修改内容及可用的恢复操作，不承诺任意外部动作都可撤销 |
| 取消与重开应用 | 区分取消中、已取消、结果待确认和可恢复会话 |
| 查看消费 | 显示服务端实际用量和扣费，单独表达尚未结算的暂扣金额 |
| 充值 | 打开既有网站流程，返回后以服务端确认的到账结果刷新余额 |
| 退出账户 | 撤销本设备授权并清理可用凭据，隔离其他账户的数据 |

## 首次使用流程

安装 → 启动 → 登录 Bamboo → 核对账户可用状态 → 选择或接受默认模型 → 开始会话；需要本地操作时再授权工作区。

需要补齐邮箱验证、政策确认或额度时，只在相关步骤展示当前阻塞原因及可执行的下一步，不让用户处理后台渠道配置。

“登录即可使用”不等于无限免费使用。现有后端的新账户默认缺少模型调用权限且余额为零；自动开通与首次体验额度需要在后端产品规则中确定。客户端不得绕过这些条件，也不得先行承诺免费额度。

## 首版暂不纳入

- 自建模型训练、模型托管或独立钱包与支付结算。
- 重新实现整套 Agent 引擎。
- 公开插件市场、移动端、团队管理和跨设备完整会话同步。
- 默认执行无人值守的全盘文件操作、任意命令或电脑控制。
- 一次性适配全部模型及其所有协议能力。

## 默认体验

普通用户默认使用 Bamboo 管理的模型目录。模型选择只提供已对目标工作流验证过的选项。具体默认模型和成本档位依据接入验证决定，不在客户端永久写死厂商模型名。

中英文体验一并设计，沿用网站的新用户默认英文及用户语言偏好方向。不可操作状态要与真实服务端条件一致。
