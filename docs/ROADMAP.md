# 实施路线

以下阶段是后续工作的顺序与验收依据，不代表自动启动后续开发。用户指定某阶段或具体实现任务后，按对应范围推进。

## 阶段 0：仓库初始化

状态：已完成文档与配置初始化，无应用实现。

- 建立独立本地 Git 仓库和初始分支。
- 明确官方 DeepSeek Harness 桌面端路线。
- 记录产品范围、架构边界、协作规则及上游来源。
- 配置文本格式和忽略规则。
- 保留只读用途的上游远端，不设置 Bamboo 推送远端。

验收：只有文档与仓库配置；相对链接有效；无凭据、依赖或应用源码；本地初始提交与工作区状态可核对。

## 阶段 1：上游基线接入

状态：未开始。

选择明确上游提交并按 UPSTREAM.md 保留历史接入。核对开发环境、依赖、许可、运行时分发及平台要求，复现上游桌面启动。

验收：在选定平台按文档启动；记录实际命令、版本和结果；应用数据与官方安装隔离；不把开发模式成功当成发布验收。

## 阶段 2：Bamboo 模型调用验证

状态：未开始。

通过上游扩展点接入 Bamboo 网关，先用受控测试账户验证选定模型。覆盖主对话、辅助调用、流式响应、工具结果回传、取消和上下文恢复。

验收：完成一个真实可核对的本地任务；所有模型调用可在 Bamboo 请求记录中关联；明确哪些能力和模型未验证。真实收费调用需在具体执行授权范围内进行。

## 阶段 3：账户与首次使用

状态：未开始。

与后端确定设备授权契约，完成浏览器登录回到应用、系统凭据存储、退出、过期及撤销。确定账户开通与体验额度规则，拉取模型能力并设置经过验证的默认模型。

验收：全新用户不需要手动复制 API Key；现有权限、邮箱与额度条件得到准确处理；多账户数据隔离；失效授权不能继续调用。

## 阶段 4：首版产品体验

状态：未开始。

完善品牌、会话、工作区授权、工具审批、文件修改展示、任务取消和恢复、用量与费用展示、中英文文案及网站充值入口。

验收：用已确定的典型任务走通完整流程；结果不明时可查询记录；暂扣和实际扣费区分正确；窗口和任务状态一致。

## 阶段 5：安装与发行

状态：未开始。

确定首发平台，配置 Bamboo 应用标识、签名、更新源和分发地址，验证首次安装、升级、卸载、数据保留和故障恢复。

验收：每个声称支持的平台均有安装包验收；许可与第三方通知完整；没有上游生产凭据或收集地址残留；发布由明确的发行任务触发。

## 后续第一个具体任务

确定一个上游基线，在隔离分支中导入并复现官方桌面启动。此时再补齐真实开发命令和依赖要求，暂不把登录、计费与全部 UI 改造合并进同一个任务。
